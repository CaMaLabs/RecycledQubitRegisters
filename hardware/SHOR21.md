# Real IBM QPU compiled Shor test: N=21

`ibm_shor21_matched.py` extends the real-QPU register-recycling test beyond the canonical `N=15` demonstration.

## Why N=21 is a harder test

The benchmark uses `N=21`, `a=2`, whose true order is `r=6`.

Unlike the `N=15`, `a=2`, `r=4` case:

- `r=6` is not a power of two;
- most ideal QPE peaks lie between exact binary grid points;
- continued fractions are genuinely needed;
- every `U^(2^k)` phase-estimation round is nonidentity.

The standard factor step is unchanged: once `r=6` is recovered,

`gcd(2^(r/2)-1,21) = gcd(7,21) = 7`

and

`gcd(2^(r/2)+1,21) = gcd(9,21) = 3`.

## Compiled orbit encoding

A generic modular multiplier for `N=21` would use a 5-qubit work register and would be too deep to make a useful NISQ hardware comparison with the current generic synthesis in this repository.

Instead, the real-QPU experiment uses an exact compiled encoding of the six-state multiplicative orbit of 2 modulo 21:

| exponent label | modular state |
|---:|---:|
| 0 | 1 |
| 1 | 2 |
| 2 | 4 |
| 3 | 8 |
| 4 | 16 |
| 5 | 11 |

The six labels fit in a 3-qubit work register. Multiplication by 2 modulo 21 becomes `+1 mod 6` on these labels; the two unused computational basis states are left fixed.

This is a compiled orbit encoding, not a generic 5-qubit modular multiplier and not a claim of large-RSA scalability. The work register is still coherent quantum state, and the phase is generated by controlled modular-orbit evolution rather than injected.

## Architectures

For `m` phase bits:

- **wide:** `m` phase qubits + 3 work qubits;
- **recycled:** 1 reusable phase qubit + 3 work qubits.

Both circuits are submitted in the same IBM job and are given the same initial physical work-register sites. The transpiler may route logical states later in the circuit.

## Run local self-test

```bash
python hardware/ibm_shor21_matched.py --phase-bits 6 --self-test
```

The script exhaustively verifies the compiled `+1`, `+2`, and `+4 mod 6` work-register permutations before constructing any IBM job.

## Transpile only

```bash
python hardware/ibm_shor21_matched.py \
  --backend ibm_fez \
  --phase-bits 6 \
  --shots 512 \
  --transpile-only
```

No QPU job is submitted. Inspect logical width, depth, circuit size, CZ count, selected physical region, and mid-circuit-measurement calibration first.

## Real matched run

```bash
python hardware/ibm_shor21_matched.py \
  --backend ibm_fez \
  --phase-bits 6 \
  --shots 512 \
  --max-execution-time 90
```

The output reports factor recovery, Wilson intervals, total-variation distance and Hellinger fidelity to the exact finite-precision order-6 QPE distribution, plus matched wide/recycled resource counts.

## Prior N=21 hardware work

`N=21` has been factored on IBM hardware before with compiled circuits. In particular, Skosana and Tame, *Scientific Reports* 11, 16599 (2021), used `a=4`, a compressed 2-qubit work register, and three control qubits. Their paper noted that a single recycled control qubit could further reduce resources once mid-circuit measurement and real-time conditional operations were available.

This repository does not claim first factorization of 21. The experiment here asks a different architecture question: with current IBM dynamic-circuit support, how does an actively recycled control register compare with a simultaneous wide control register under the same-job/shared-work-placement methodology?
