## Exactly one new experimental change, frozen

Replace **ONLY** the old ripple-comparator implementation in `public_threshold_predicate(qc,x,t,flag,carry,chain,controls,geq)` of the verified best. Keep the original `constant_add_from_prefix_carry`, original correction `optimized_modadd`, and original cached enable registers/`verified.build` unchanged. The comparator must implement public `x<t` as XOR of **disjoint prefix minterms**, for every public unsigned `t` in `1..2^w-1` and `w<=6`:

For each **set bit** i of threshold t, an x less than t falls into exactly one case: x agrees with all higher public t bits and x[i]=0. Thus `[x<t] = XOR_{i:t_i=1} ([x_{>i}=t_{>i}] AND [x_i=0])` (the terms are pairwise disjoint). If `geq=False`, toggle `flag` for each minterm and for the external enable condition; for `geq=True`, first toggle flag on external enable (complement `x<t`), then toggle on exactly the same enabled disjoint minterms. Each minterm is compiled from **only explicit X/CX/CCX** using previous verified `primitive.multi_x` with temporary public bit inversions for negative comparison literals, each inversion undone before the next term; clean chain remains zero. No new ancillas; old six clean carry qubits remain unused by this comparator. This is NOT a lookup table across 64 x or order-orbit-specific encoding: it synthesizes a comparator from public threshold bit positions, works on variable width w and N, with worst-case O(w²) Toffoli control work for a dense threshold. Candidate may be MORE expensive; record that honestly.

Keep the original public threshold **trailing-zero shortening**, so the new comparator sees only `x[s:]>=t>>s` when `t=2^s*u`. Only comparator network construction changes. No parameter search, no hand-selecting constants, no precomputed factors, or oracle true multiplicative order. Both a=2 and a=8 share the same implementation.
