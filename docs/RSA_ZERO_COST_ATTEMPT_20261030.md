# RSA target selection and zero-external-cost attempt

Lead: Chase Lunsford / CaMaLabs. Date: October 30, 2026.

**Result: RSA-2048 remains unfactored by this attempt. No general RSA break.**

The selected primary target is the published 617-digit RSA-2048 challenge,
transcribed from the challenge PDF attributed to RSA Inc:
https://dev.mysterytwister.org/media/challenges/pdf/mtc3-rsa-38-en.pdf.
Only its public modulus and a chosen e=65537 enter workers. The challenge
itself asks for factors, not decryption of a supplied ciphertext. The exact
target and six fixed arm budgets were frozen in a manifest before execution.

## Actual primary attempt

The original receipt is `results/rsa_zero_cost_20261030/attempt.json`.

| Local method | Wall cap | Outcome |
|---|---:|---|
| Small-prime/perfect-power screening and 8,192 Fermat positions | 2 s | Completed without a factor |
| Wiener continued-fraction attack on the chosen public exponent | 2 s | Completed without a factor |
| Dark Star public odd-power/repeated-square/GCD shortcuts | 4 s | Completed without a factor; classical work only |
| Pollard p−1, B=100,000 | 8 s | Completed without a factor |
| GMP-backed Brent rho, explicit operation cap | 15 s | Completed without a factor |
| ECM, B1=20,000/B2=200,000, at most32 curves | 30 s | Wall deadline reached; censored, not a completed ECM failure |

Actual primary-arm subprocess wall time was about38.21 seconds. This was a
bounded screen, not an exhaustive attack and not a meaningful security lower
bound. General number field sieving was not run: no GNFS engine is installed,
and no credible RSA-2048 resource plan exists in this environment. More rho
iterations alone do not bridge that gap. No new factoring algorithm or
quantum speedup is claimed.

## Functional controls, kept separate

Three fresh disposable keys were generated by the parent. Workers received
only N/e, not secret primes, seeds, private exponents, or messages:

- 2,048-bit RSA with deliberately adjacent primes: recovered by the Fermat screen.
- 2,048-bit RSA with a deliberately tiny private exponent: recovered by Wiener.
- 64-bit RSA control: recovered by Brent rho.

All three returned exact prime-factor certificates. Reconstructed private
exponents passed seven public textbook-RSA round-trip checks, including
messages divisible by either prime. This validates key reconstruction after
factoring; it does not test a production padding implementation. The first
two keys are intentionally vulnerable and the third is tiny. None counts as
a break of a correctly generated modern RSA key. Their disposable secret
material is included in the receipt only as a reproducible control result.

## Quantum feasibility decision

The existing masked Fibonacci code remains an exponential tiny-group
reference. It is not an RSA-sized quantum execution. The Van Kirk/Gidney
streamed-Regev construction with leading space4n would have a leading term
of8,192 **logical** qubits at n2048, excluding lower-order terms and physical
error-correction overhead: https://arxiv.org/abs/2610.06733.
This is one construction's accounting, not a universal qubit lower bound.

The repository's real hardware evidence is the separate N15 pilot. The
previous exact N35 ladder candidate lost all24 compiler pairs on the
explicitly synthetic line target. No available fault-tolerant schedule or
device establishes a feasible quantum attack here. The larger physical
resource projection https://arxiv.org/abs/2505.15917 is a theoretical
engineering estimate, not hardware we can invoke for free. No QPU run was
submitted or implied by this resource check.

## Cost and reproduction

External compute spend: **0**. QPU jobs: **0**. No paid API, rental, hosted CI
job, or billing-capable service was requested. The run used this session's
local CPU only; it does not claim that computation has no underlying energy
or infrastructure cost. Publication commits carry `[skip ci]`; this is not
a request for more hosted compute or an ongoing background task.

From the repository root:

```bash
python3 -m venv .venv-rsa
. .venv-rsa/bin/activate
python -m pip install -r requirements-rsa-zero-cost.txt
python -m unittest discover -s hardware -p test_rsa_zero_cost_attack.py
python hardware/rsa_zero_cost_attack.py --output results/rsa_zero_cost_20261030/rerun.json
```

Dependencies are SymPy1.14.0 and gmpy2 2.2.1. ECM uses the inspected pinned
SymPy one-factor primitive, avoiding loss of a partial factor to subsequent
recursive work. Software errors are fatal; deadlines remain explicitly
censored. Target factors are accepted only after exact multiplication and
primality verification. This attempt does not justify claiming that RSA or
ML-KEM has been broken.
