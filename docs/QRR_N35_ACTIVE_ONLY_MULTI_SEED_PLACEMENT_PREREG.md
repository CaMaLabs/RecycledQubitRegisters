# Preregistered: N35 active-only relative-phase latch seed robustness, IBM Fez target CPU only

Research lead/original program: **Chase Lunsford / CaMaLabs**. Frozen 2026-10-17 **before any new multi-seed compilation**. Absolutely **ZERO real IBM quantum hardware jobs, zero Sampler/Estimator, zero free/Open Plan or paid runtime**. The target's hardware information is READ ONLY, to be used for local CPU compilation.

## Evidence and exact question

The [verified prior public N35 relative-phase comparator carry work](QRR_N35_RELATIVE_PHASE_RIPPLE_CARRY_RESULT.md) established the phase-exact baseline `neither`: one controlled modular multiplier on all 6-bit residues, including invalid-state identity, with base2 native CZ**9263**, depth**21772**, and public cubic base8 CZ**9426**, depth**21933**. [Original isolated latch-family result](QRR_N35_RELATIVE_PHASE_LATCH_FAMILY_ABLATION_RESULT.md) has a separately verified `active_only` candidate: base2 CZ**9042**, depth**21541**; cube8 CZ**9156**, depth**21820**, each from *one* optimization seed 8776. All the 42,672 comparator, 1,584 modular-add and 128 whole source-gate phase-exact basis checks, plus 8 local RCCX probe checks, passed. Both design types have 32 logical application qubits and all 25 auxiliary qubits return to zero with exact output quantum complex phase+1. All original JSONs are archived; they stay unchanged.

**Question:** does substituting just the *single active cache RCCX compute/inverse pair* consistently improve native `ibm_fez` CZ and depth over the identical original comparator-only `neither` source, when the transpiler's **seed** varies with all other inputs fixed? This is a placement/compiler robustness check, not a new arithmetic optimization and NOT a live QPU Shor/factoring experiment.

## Frozen design

- Use same original old `neither` circuit via `qrr_n35_relative_phase_ripple_carry.verified.build(base)` and identical `active_only` circuit via `qrr_n35_relative_phase_latch_families.build_variant(base,"active_only")`. Both import unchanged verified phase-aware shortened ripple comparator and prefix-carry arithmetic, same public N35 base2/cube8, same 32 logical qubits/25 initially clean auxiliaries. The **ONLY difference** is the 2 clean active RCCX/adjoint instructions in place of 2 exact CCX. No other variants or shortcuts from true multiplicative order, factorized 12-state orbit or precomputed truth table; both process ALL 64 six-bit inputs, controls and superpositions.
- Precisely **eight fixed integer seeds**, no additions/deletions or post-result cherry picking: `[11,37,101,409,8776,12011,20261,45673]`. Optimization level=**1**, `qiskit~=2.5.2`, `qiskit-ibm-runtime~=0.47.0`, `generate_preset_pass_manager(backend=backend,optimization_level=1,seed_transpiler=seed)`; exact same read-only `ibm_fez` backend object, same target time, and same Qiskit code within EACH job.
- 2 independently executing GitHub Actions jobs: base2, base8. Each job compiles 8 paired seeds×2 circuits=16 native CPU compilations; 32 new compiles in total. Keep order fixed and **run original `neither` first, active-only second** for each seed. Do not change optimization, routing, compiler initial layout or Qiskit target basis; no seed search for a favorable seed; don't substitute a simulator or one public base.
- Test **BEFORE** any backend access: 8/8 actual RCCX local latch +1-phase checks, **42,672/42,672** standalone emitted-comparator complex-phase cases, **1,584/1,584** modular addition complex-phase cases from all16 public constants, and **128/128** complete actual emitted-gate basis×control cases **for EACH original `neither` AND `active_only` variant**, every 25 auxiliary qubits returned zero, complex phase exactly +1, unchanged controls, invalid y identity. Confirm base-specific source counts from previously archived original documents, with active-only RCCX +2 and CCX -2 and CX/X unchanged. Source proof once per arm suffices since seed changes only target compiler, not source circuit. If semantic proof fails, save error and **never read backend**.
- Each pair records full original-and-active native `count_ops`, CZ, depth, compiled ISA width, size, elapsed and seed; test native count consistency and any zeros; retain **every** result/failed seed in an original JSON. No shifting acceptance criteria after seeing them.
- Mandatory **seed 8776 anchor** from original frozen receipts: base2 `neither CZ9263 depth21772`, `active CZ9042 depth21541`; cube8 `neither CZ9426 depth21933`, `active CZ9156 depth21820`. Reproducing the anchor confirms compiler/target comparability to frozen earlier outputs; if source CI metadata differs or target changed, record **anchor drift**, do not silently call cross-date values reproducible. Continue paired same-target comparisons and state caveat; no device submission.
- Report CZ/depth delta **for every seed** `active - neither`, per-base median and min/max/range, number of **both CZ & depth strictly lower** and separately each metric improvement; median of paired deltas (median CZ, median depth). At full two-arm level total16 seed-pairs. Also report worst negative regressions instead of only best seed and distinguish native resource savings from quantum-fidelity performance (no device run).

## Frozen scientific outcome criteria

**Robust engineering PASS** only if **BOTH bases** satisfy ALL:
1. Both variants phase-exact proofs pass on all 8+42672+1584+128 input cases, gate sources actually differ only in 2 active RCCX and 2 CCX counts, all 8 paired seeds successfully compile; 8776 anchor exactly reproduces existing original source metrics with no backend metadata drift.
2. At least **6/8 seeds** have **both native CZ strictly lower AND native depth strictly lower** for active-only vs matched neither on that base. Also the median **paired** CZ delta is <0 AND median **paired** depth delta <0. Do not replace with a best-seed success if the paired win threshold fails.
3. If any criterion fails, report **NOT ROBUST** and retain full negative/partial receipts. If 8776 drift occurs, call robustness INCONCLUSIVE relative to previous target rather than a confirmed robust gain regardless of other seeds.

**Hardware feasibility separately immutable:** the absolute native CZ must be ≤**800** and depth ≤**2000** for BOTH bases on any proposed layout; even satisfying this proxy would NOT authorize a device submission under this experiment. Never claim a four-QPE-round Shor trial, quantum factoring a³ speedup on hardware, a theorem, RSA break or benchmarked quantum hardware noise performance from native CPU compilation.
